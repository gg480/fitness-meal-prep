# 方案设计：v3.1 收尾——周活动量双环 + 进阶提示界面化（详设 v1）

> 对应 SPEC.md §7.8（v3.1.0 增量遗留两项）。07 轮已交付训练体系主体（跟练/周历/课表库/动作库），
> 7.7 补打卡、7.6 组间倒计时、7.6 末段动图库均已收口；本设计只覆盖 SPEC 明确未做的剩余两项。

## 1. 范围与非目标

**做**：
1. 周活动量双环（§7.8）：有氧环 = 周内 cardio_logs.minutes 合计 / 150–300 目标带；力量环 = 周内 workout_logs 条数 / ≥2。两种口径**不混折**（力量条数不折算成有氧分钟）。
2. 进阶提示界面化（§7.1 + §7.8）：`progressionHint()` 纯函数已在 07 落盘（frontend/src/training.js L170-204，五规则全实现、training-calc-audit ⑤段已测），但全工程 0 处调用。本设计把它接到「下一练」卡片上，练前可见。

**不做**（P2 冻结）：晨脉趋势、力量曲线、deload 自动化（只提示不自动改排课）、课表自定义。

## 2. 数据口径

- 周 = 自然周，周一为一周之始（复用 cardio.js `weekStartKey` L132-138，勿重写——getDay 周日=0，公式 `(getDay()+6)%7`）。
- 有氧分钟：store.cardio（cardio_logs 全量）按 `date >= weekFrom && date <= todayKey` 过滤 Σ minutes。
- 力量条数：store.workouts（近 90 天全量，store.js L26）按同窗口过滤条数。
- 输入快照：`store.bootstrap()` 已并行拉全量 cardio+workouts（store.js L223-239），**无需新增 API**。

## 3. 纯函数设计（frontend/src/training.js 新增）

```js
/**
 * 周活动量（SPEC §7.8 双环口径）：有氧看分钟（150–300 目标带）、力量看次数（每周 ≥2 练）。
 * 两种口径不混折——力量课时不折算成有氧分钟（强度/时长分布完全不同）。
 * @param {Array<{date:string}>} workouts 本周内力量课（传入前可不管窗口，函数内部过滤）
 * @param {Array<{date:string,minutes:number}>} cardioLogs 有氧记录全量
 * @param {string} todayKey 今天 YYYY-MM-DD
 * @returns {{weekFrom:string, cardioMin:number, cardioPct:number, cardioZone:'low'|'ok'|'high',
 *            strengthCount:number, strengthPct:number, strengthZone:'low'|'ok'|'high'}}
 */
export function weekActivity(workouts, cardioLogs, todayKey) { ... }
```

- `weekFrom = weekStartKey(todayKey)`（training.js 新 import 自 cardio.js；已核实无循环依赖——cardio.js 只 import utils.js）。
- 有氧：`cardioMin = Σ minutes(本周)`；`cardioPct = clamp(cardioMin/150*100, 0, 100)`（150 达标，300 封顶展示）；zone：`<150→'low'`、`150–300→'ok'`、`>300→'high'`（超量提示适度，不惩罚）。
- 力量：`strengthCount = 本周 workouts 条数`；`strengthPct = clamp(count/2*100, 0, 100)`；zone：`count>=2→'ok'`，`1→'low'`，`0→'low'`（展示层区分 0 与 1）。
- minutes 缺失按 0 计（cardio_logs.minutes 是 NOT NULL，防御旧数据）。

## 4. 进阶提示接入（frontend/src/views/TrainingView.vue）

- `historyFor(exKey)`：store.workouts nested sets 摊平 → `w.sets.filter(s => s.exerciseKey === exKey).map(s => ({date: w.date, setNo: s.setNo, reps: s.reps, toFailure: s.toFailure}))`，多堂课合并（progressionHint 内部按 date 归组）。
- `nextHints` computed：`nextList` 每个动作 → `progressionHint(historyFor(ex.key), { weekAge: ph.value.weekAge })`，`action !== null` 才保留。`ph` computed 已有（L66 phaseOf）。
- 展示：下一练卡 ex-list 每行动作块下加 hint 行（`v-if="nextHints[ex.key]"`），icon/文案按 action：`up→加重 ▲`、`hold→维持 ●`、`down→降档 ▼`、`deload→减量周 ⏸`；reason 文案直接用函数返回值（已是中文）。
- 不阻塞交互：提示纯展示，不拦截「开始训练」。

## 5. 双环展示（TrainingView 周历视图）

- 挂点：周历 section（v-else-if="view === 'week'"）sec-head 下、wk-grid 上，加一行 `.rings-row`：两个环形（svg circle r=26 viewBox 0 0 64 64，fg dasharray/dashoffset 同断食卡视觉语言——绿主色、灰轨道、-90° 起笔）+ 底注文案 `有氧 X 分钟 · 目标 150–300` / `本周 X 练 · 每周 ≥2`。
- 环色：ok → var(--primary) 绿；low → 灰 #9e9e9e；high → 橙 #ff7043（超量同样警示色，文案「已超目标带，注意恢复」）。
- 数据源 `wa` computed = `weekActivity(store.workouts, store.cardio, dateKey())`。

## 7. 验收脚本：verify/training-progress-audit.mjs（新建）

- **[A] weekActivity 纯函数**（import 自 frontend/src/training.js）：
  1. 空输入 → cardioMin 0 / strengthCount 0 / 双 zone low / weekFrom=本周一；
  2. 本周 90 分钟有氧 → cardioPct 60 / low；本周 150 → 100/ok；400 → 100 钳/high；
  3. 本周 2 练 → strengthPct 100/ok；1 练 → 50/low；0 练 → 0/low；
  4. 跨周不计：上周 cardio 与上周 workout 均不进入本周口径；
  5. 周一为界：周日数据落上周、周一数据落本周（用固定 todayKey 构造 ±1 天）。
- **[B] 界面挂接源码 grep**（TrainingView.vue）：`weekActivity` 导入+`rings-row` 节点、`progressionHint` 导入+`nextHints` computed+hint 展示行、无 TODO 残留。
- **[C] API 输入完备性**（spawn backend，DATA_DIR=mkdtemp 隔离）：POST /cardio 本周两笔（minutes 60/90）→ GET 回读；POST /training/workouts 本周两笔含 sets（exerciseKey/setNo/reps/toFailure）→ GET nested sets 字段齐全——证明 weekActivity 的输入在真实链路可得。
- 进 training-progress-audit 的回归：progressionHint 五规则细粒度断言已由 training-calc-audit ⑤段覆盖，本脚本不重复（只引源码 grep 证明调用存在）。

## 9. 风险与对策

- store.cardio 分钟单位：cardio_logs.minutes 即分钟数（cardioSummary 同口径），无双计风险。
- 旧数据 sets 缺 toFailure → progressionHint 视为非力竭（函数已处理 undefined，training-calc-audit 已测）。
- nextList 动作 key 来自排课/轮换，历史中可能无该动作记录 → historyFor 返回空数组 → progressionHint 返回 null → 不展示（正常路径）。
