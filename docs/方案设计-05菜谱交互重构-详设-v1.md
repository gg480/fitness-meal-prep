## 1. 信息架构：配方页固定三段式（Q4）

```
┌─ 段A 目标与总览（只读卡）──────────┐
│ 今日日型·配额摘要（c/p/f/kcal）    │ → 点卡跳 04 目标页
│ 每份营养 per + 份数 + 锅数 potDaysOf│
├─ 段B 食材清单 ────────────────────┤
│ [搜索框]（页内，见 §2）             │
│ [常用20 横滑条]                     │
│ [品类分层入口]（抽屉）               │
│ 食材行：名称·份量·[−][+]·锁🔒·删   │
├─ 段C 生成与保存 ──────────────────┤
│ [自动生成] [存入配方库] [另存新配方] │
│ [去做饭 ▸]（页内切子视图）           │
└──────────────────────────────────┘
```

- 段A 数据全部现算（quota 引擎/potDaysOf 冻结口径），只读展示，不在此页改目标。
- 段C「去做饭」= 页内子视图切换（store 子状态，非独立 Tab）。

## 2. 加食材 = 1 步（问卷裁决）

- **搜索**：段B 顶部页内搜索框，输入即过滤 foods 全表（名称/别名 contains）；结果行**点击即入配方并 +1 份**（已有则 +1 份，badge 微反馈），无弹窗、无确认步。
- **常用 20**：按历史 recipes 食材出现频次排序前 20（纯前端从 recipes 表统计，无新表、无新设置），横滑 pill 条，点击同「即入+1」。
- **品类分层**：抽屉列品类（肉禽蛋/主食/蔬果/奶豆/油脂调料/其他——实施时核对 foods 既有 category/nature 字段，无则用 constants 映射，可逆决策不问询）；层级≤2 层，条目点击同「即入+1」。
- 自定义食物入口保留（submitCustomFood 既有链路不动）。
- 数量调整：点食材行展开行内 stepper（±步进沿用既有 stepFood 粒度），触控目标 ≥44px。

## 3. 生成与保存反馈（问卷痛点「保存/生成无反馈」）
