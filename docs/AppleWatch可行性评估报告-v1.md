# Apple Watch 可行性评估报告 v1

> 计划项：09-AppleWatch可行性评估报告　阶段：方案设计　日期：2026-11-24
> 结论先行：**手表专项需求本轮暂缓实施，本报告供后续决策**（问卷「原生不可行则暂缓」预设 + 第二轮 grill Q11/Q12「按推荐来」确认）。

## 1. 用户现状与需求原文

- 设备：iPhone（新款机型，S7 之后/Ultra 配对），**无 Mac、不打算购买**；手表=新款 Apple Watch。
- 想要的手表能力（问卷原答）：①看当前动作+记一组 ②组间倒计时 ③实时心率 ④心率数据同步 ⑤手表「体能训练」记录导入。
- 决策锚点（问卷）：「原生不可行则暂缓该需求」「先出可行性评估报告再定」。

## 2. 技术路线事实核查（subagent ios-watch-research，2026-11-24）

| 路线 | 可行性 | 关键事实 | 来源 |
|---|---|---|---|
| PWA + Web Push（自建服务端推送） | ✅ 可行 | iOS/iPadOS 16.4+ 主屏 Web App 支持 Push API+Notifications API+Service Worker，走 APNs，无需开发者账号；授权须用户交互触发。官方明确通知「show on the Lock Screen, in Notification Center, **and on a paired Apple Watch**」=自动镜像到手表 | [WebKit 博客](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)、[Declarative Web Push (18.4+)](https://webkit.org/blog/16535/meet-declarative-web-push/) |
| Web Bluetooth（读 BLE 心率带 0x180D） | ❌ 不可行 | Safari on iOS 全版本（含最新 27.x）不支持 Web Bluetooth；Chrome/Android 可。iOS 网页无法直读 BLE 心率 | [caniuse](https://caniuse.com/web-bluetooth) |
| 快捷指令 App（时间自动化+计时器/通知动作） | ⚠️ 有限可行 | 按钟点触发「显示通知/开始计时器」；可用 iCloud 链接分发指令、`shortcuts://` URL 从 Safari 调起；「开始计时器」跑系统时钟、手表原生显示、离线可靠。限制：需手动安装配置、只能按钟点触发、通知以「快捷指令」名义镜像 | 快捷指令官方文档 |
| 表盘复杂功能 / Smart Stack | ❌ 不可行（本轮） | 仅原生 App 可做，需 Xcode+付费开发者账号；用户无 Mac 不打算搞 | Apple 开发者文档 |
| 手表原生 App（独立 watchOS App） | ❌ 不可行（本轮） | 同上，需 Mac+Xcode+付费账号 | Apple 开发者文档 |

## 3. 映射到用户的 5 个手表诉求

| # | 诉求 | 本轮可行路径 | 判定 |
|---|---|---|---|
| 1 | 看当前动作+记一组 | 手机 PWA 跟练页承担（07 模块）；手表侧无可行载体 | 手机做，手表不做 |
| 2 | 组间倒计时 | 手机端计时器已有（07 模块）；手表侧可由快捷指令「开始计时器」兜底（离线可靠） | 手机做，手表兜底 |
| 3 | 实时心率 | Web Bluetooth 被 iOS 禁→网页读不到 BLE 心率；唯一路径=原生 App（约束下不可行） | **本轮明确不可行** |
| 4 | 心率数据同步 | HealthKit 需原生 App；网页无 HealthKit 通道 | **本轮明确不可行** |
| 5 | 手表「体能训练」导入 | HealthKit 通道同上，网页无解 | **本轮明确不可行** |

**净结论：在「无 Mac、零原生开发」约束下，手表侧 5 项诉求全部不可行或降级为手机侧承载。**

## 4. 唯一保留的可行增量：PWA + Web Push

- 前提两步（用户手动）：Safari 打开应用→「添加到主屏幕」→打开推送授权。
- 能得到什么：轻断食到点提醒、训练日提醒、规则引擎触发提醒——通知出现在 iPhone 锁屏/通知中心，**并自动镜像到 Apple Watch 手腕上**。
- 代价：需要新增后端推送服务（APNs 密钥+订阅管理表）+ Service Worker，**超出本轮「零新依赖」技术约束**，建议放后续轮次立项。
- 离线兜底：iOS 18.4+ 支持 Declarative Web Push；快捷指令时间自动化可做「到点提醒吃饭/喝水/训练」类离线提醒（用户需手动配置，通知以「快捷指令」名义发出）。
- 最大限制：WebKit 无本地预约通知（无 showTrigger）——「准点」提醒必须服务端准点推送，依赖网络与服务器时钟；快捷指令按钟点触发的自动化可兜底离线场景。

## 5. 建议

1. **本轮（04-08、10）不做任何手表功能**——符合问卷「原生不可行则暂缓」预设。
2. 把「PWA + Web Push 提醒」列为**下一轮候选模块**（唯一可行增量，成本=后端推送服务+SW），与用户确认后再立项。
3. 「实时心率/心率同步/体能训练导入」三项在本轮约束下**不可行**（除非未来购置 Mac 转原生开发），如需推进只能换路线。
4. 建议用户现在就做「添加到主屏幕」这一步（本轮 Web App 也能加主屏，只是没有推送），为后续轮次的推送能力铺路。
