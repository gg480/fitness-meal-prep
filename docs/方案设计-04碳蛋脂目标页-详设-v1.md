# 方案设计-04碳蛋脂目标页-详设-v1（草案，待大纲卡落决后生效）

> 计划项：04-碳蛋脂目标页 | 阶段：方案设计 | 日期：2026-11-24
> 输入：方案大纲 v1 §4-04 + 契约 T-102 冻结口径 + 问卷 Q5 系列裁决
> 铁律：引擎不动（契约 §7.1 五处冻结不碰），本页只做「展示 + 入口」，符合「生成逻辑不动只换交互外壳」裁决。

## 1. 目标与范围

新增独立「目标」Tab：一屏看清**今天该吃多少碳蛋脂（目标）vs 实际折算（已吃）**，支持日型自动推断+手动覆盖，联动配方页。不做速查小抄、不做手动已吃台账（问卷裁决）。

## 2. 页面结构（自上而下）

```
┌──────────────────────────────┐
│ ① 日型卡（今日身份）         │  自动推断结果 + 依据 + 手动改
├──────────────────────────────┤
│ ② 日目标总览（大字）         │  c / p / f / kcal 四个数
├──────────────────────────────┤
│ ③ 全天差额条                 │  目标 vs 已吃，红黄绿
├──────────────────────────────┤
│ ④ 每餐明细（可展开）         │  每餐目标 vs 已吃差额条 × N 餐
├──────────────────────────────┤
│ ⑤ 底部操作条                 │  「去配方页按今日目标生成」入口
└──────────────────────────────┘
```

### ① 日型卡
- 展示 `store.todayDayType`（utils.js:60 `pickDayType(reg, fallback, hasWorkout)` 的结果）+ 推断依据文案：day_logs.day_type 已登记→「今日手动登记：训练日」；未登记且有力量课→「今日有力量课，自动按训练日」；未登记无课→「按默认（设置：rest）」；全空→「无训练」。
- **手动覆盖**：三个 pill（训练日/休息日/无训练）→ `PUT /api/day-logs` 的 dayType 字段（day-logs.js:131 `normalizeDayType`，T-126：null=未登记与 none 区分）。覆盖后可「清除登记」回到自动推断（dayType 传空）。
- 训练日时显示 trainSlot 七值选择器：改动写 `settings.trainSlot`（settings.js:12 既有校验通道，引擎从 settings 读，day_logs 无此列——沿用现状，不新增列）。
- 只读角标：carbStage（early/late，来自 settings.carbStage，减脂末期自动切）；calcMode 非 quota 时顶部提示「当前为 TDEE 模式，目标页按配额口径显示」。

### ② 日目标总览
- 数据 = `calcQuotaProfile(settings, bodyWeight, todayDayType)`（store.js:69 现成），大字展示 c/p/f/kcal + 区间带（band）小字「×g/kg 口径」。
- 外食叠加：当日 day_logs.outing 非空时，目标侧展示 `adjustForOuting`（utils.js:364）后的**调整后目标**，并保留原始目标对照（含 over 超卡明示）。

### ③④ 差额条（核心交互）
- **已吃口径（Q2 裁决=配方锁定份量折算；对齐 v3.3 实际端账本）**：已吃 = `intakeBreakdown(store.today)`（utils.js:1250）——三段汇总：`portion`（早/午/晚，事件 `kind:'portion'` 自带 per 快照，吃几份 × 每份宏）+ `snack`（加餐槽位）+ `outing`（`outingNutri` 折算）。**计划端与实际端两本账互不穿透**（SPEC §8：顶部汇总不含旧库存核销事件，混算即双计）——本页只读实际端 `intakeBreakdown.total`，不复用 `meals` 字段（那是计划份数，不是已吃）。
- **未记录态**：当日无 `portion` 事件且 `outing` 为空 → 显示「未记录」灰态，不算 0、不参与红黄绿判定（与 Q2 裁决一致）。
- 防漂移：`portion` 事件的 per 快照在落账时刻冻结（确认时刻「每份」营养），配方中途改动不篡改历史已吃——天然满足，无需再读 `per_snap`。
- 红黄绿沿用现有门禁口径（|kcal−目标|≤10% 绿 / ≤20% 黄 / 超 红），per-meal 粒度同规则。
- ④ 每餐明细 = `mealTargets(todayDayType, trainSlot, quota, carbStage, slotsOff)`（utils.js:257）的 meals 数组渲染：底层 7 槽按 `slotsOff`（settings.mealSlotsOff 六餐开关）折叠后呈现，入口呈现 4 类（早/中/晚/加餐，Q5.4 裁决「底层保留 7 槽、入口呈现 4 类」）。练后餐角标硬约束 p∈[30,50] f≤20。
- 展开态：每餐显示该餐 c/p/f 三条 mini 差额条；已吃按 `PORTION_SLOTS`（breakfast/lunch/dinner/snack，constants.js:354，与后端 log-events.js 逐值一致）+ `outing.dishes[].slot`（OUTING_SLOTS 五值）按槽位归集比对； snack 槽位=加餐段单列（不占正餐配额，SPEC §8.3）。

### ⑤ 底部操作条
- 主按钮「去配方页按今日目标生成」→ 切 recipe Tab（联动=跳转+配方页头部显示今日目标卡；生成逻辑零改动）。
- 次按钮「练后餐比例设置」→ 跳设置页高级区（练后餐比例进高级设置，Q5.7 裁决）。

## 3. 数据流与状态

- 全部计算复用前端纯函数，页内零新计算逻辑；新状态只有 `expandedMeal`（本地 UI 态）。
- 日型/份量变更 → store reactive 自动重算，无需手动刷新。
- 触点清单（供实施核对）：App.vue（Tab 栏加「目标」）、store.js（只读复用）、api.js（day-logs PUT 已有）、路由=Tab 状态切换（无 vue-router，沿用现状）。

## 5. verify 断言计划

新增 `verify/goal-page-audit.mjs`：
1. 已吃折算：`intakeBreakdown` 三段汇总正确（portion 事件 per 快照 × shares 0.5 步进；snack 单列；outing 折算）；portion 与旧核销事件不混算（双计防护）。
2. 未记录态：无 portion 事件且无 outing → 未记录（不参与红黄绿判定）。
3. 日型联动：train/rest/none 三态 × trainSlot 七值的目标矩阵与 mealTargets 断言一致（复用 meal-audit 口径）。
4. 手动覆盖：PUT dayType train → 目标页显示训练日；清空（null）→ 回落自动推断（T-126 未登记与 none 区分）。
5. 外食叠加：outing 存在时展示调整后目标+原始对照+over 明示。
6. 差额条红黄绿阈值边界（10%/20%）。
