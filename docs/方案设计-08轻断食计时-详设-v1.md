# 08 轻断食计时 · 详设 v1

> 依据：问卷裁决（16:8 日常 / 今日页小卡片入口 / 页面内提示即可 / 围度归 06 / 频率随缘 / 没用过想开始）+ grill Q10（断食=手动为主+第一餐回推兜底）。

## 0. 现状盘点

- day_logs.meals_log 事件流带 ts（portion/outing 事件），可从中提取「当日第一餐时间」。
- 今日页已有多卡布局；无任何断食状态存储。
- 打卡/打卡主流程与断食正交（断食窗口与打卡 checked_in 无关）。

## 1. 数据模型（最小）

- **day_logs 加列 `fast_state TEXT` 可空**（幂等补列，老数据 NULL）：JSON `{"goal": 16, "lastMealTs": "HH:MM", "manual": true, "endedTs": "HH:MM"|null}`。
  - goal=断食目标小时（默认 16，范围 12-24，settings 可设默认）；lastMealTs=最后一餐（或断食起点）时刻；manual=手动开始标记；endedTs=结束时刻（断食完成回写）。
  - **不加新表**：断食是「日粒度状态」，挂 day_logs 与既有哲学一致；跨日断食（过午夜）按「结束日记录」处理（endedTs 落结束当日）。
- settings 加键 `fastGoalHours INTEGER`（默认 16，白名单三处同步：seed.js/db.js/constants.js）。

## 2. 交互（今日页小卡片）

```
┌─ 断食卡（无进行中状态时）──────────┐
│ [开始 16:8 断食]  上次: 昨日 14.5h │
├─ 进行中 ──────────────────────────┤
│ ⏱ 已断食 12h30m / 目标 16h        │
│ 环形进度 + 剩余 3h30m              │
│ [吃第一餐·结束] （记录实际时长）    │
└──────────────────────────────────┘
```

- **手动为主**：点「开始」→ 记 lastMealTs=当前时刻（或用户改填具体时刻）→ 进入计时态。
- **第一餐回推兜底**：无手动开始且当日已有第一笔 portion/outing 事件 → 自动推算「昨晚最后一餐→今日第一餐」间隔，卡片显示「检测到首餐 HH:MM，昨晚末餐 HH:MM，隔窗 X 小时」+ 一键采纳为已结束断食记录（回填 fast_state，endedTs=首餐 ts）。手动开始优先，有 manual=true 时不自动推算。
- 计时展示：纯前端 setInterval 分钟级刷新，进度=now−lastMealTs；**不做通知/提醒**（问卷「页面内提示即可」；PWA Push 属 09 报告下轮候选）。
- 完成点击「吃第一餐·结束」→ endedTs 落账 + 震动 + toast「本次断食 Xh Ym」。
- 历史回溯：记录页（10 仪表盘落地前在 LogView，落地后归今日页历史区）日详情显示断食时长行。

## 3. 冻结边界

- 打卡/配额/置换引擎零关联零改动；meals_log 事件结构不动（回推只读 ts）；day_logs 既有列不动（只加列）；备份白名单补 fast_state 列名（BACKUP_COLUMNS.day_logs 数组 +1，auditBackupCoverage 绿）。
- 断食数据不参与任何规则判定（evalRules 不读 fast_state）。

## 4. verify 计划：新增 `verify/fasting-audit.mjs`

1. fast_state 幂等补列 + 白名单三处默认同步断言。
2. 手动开始/结束落账；goal 范围钳制 12-24。
3. 回推兜底：portion 首事件 ts 提取、昨晚末餐定位、manual 优先不覆盖。
4. 跨日：endedTs 落结束日；lastMealTs 昨日 → now 差值含跨夜正确。
5. 备份：day_logs 列名含 fast_state、旧备份导入跳过不报错。
6. 回推纯函数边界：无 meals_log / 空事件 / 首餐即首事件。

## 5. 明确不做（YAGNI）

自动检测进食窗口全程跟踪、多目标计划（18:6 切换）、断食打卡 streak、通知推送、Apple Health 写入。
