# 方案设计 · 配方管理体验完善（弹层式配方库管理器）v1

> 需求来源：用户 m02734「配方页的配方管理做完善一点 现在的配方管理操作逻辑很生硬」
> 状态：待 C-0044（合并卡）落决后实施
> 关联：C-0044 [计划变更] 合并卡（v3.1 双环 4 tickets + 本需求 2 tickets）

## 1. 现状与痛点

RecipeLibBar.vue（32 行）一行式操作条挤了 5 个操作：

| 痛点 | 现状代码 |
|---|---|
| 载入无预览 | 原生 `<select class="recipe-select">`，选项只有「名 + ⚠」，载入前看不到配方内容（几样食材、几份、多少 kcal） |
| 删除无确认 | `deleteRecipeFromLib`（RecipeView.vue L344-359）点「删」直接 `api.deleteRecipe`，误触即丢配方 |
| 无独立重命名 | 改名必须「输入新名 → 存配方（覆盖）」走一次全量保存；只想改名时会把当前工作区的食材/份数一起写进库 |
| 覆盖无提示 | 「存配方·覆盖N」只有按钮文案一个线索，没有 diff 预览 |
| 原生控件观感差 | select 在移动端弹原生滚轮，与 app 内自绘弹层（picker/CalendarSheet/ActionModal）风格割裂 |

## 2. 方案：一行收窄 + 弹层式库管理器

### 2.1 RecipeLibBar 收窄为「当前配方条」

保留一行，只放三件事：
- 配方名 input（保留，仍走 `update:name`）
- 「存配方」btn（保留覆盖语义与文案）
- 「配方库 N」btn（新）——打开库管理器弹层，N = recipes.length

迁出该行的操作：另存为、载入 select、删除 → 全部进弹层。「另存为」逻辑保留在 RecipeView（saveAsNew），入口移到弹层内（对当前绑定条目提供「另存副本」）。

### 2.2 新弹层 RecipeLibSheet（RecipeLibBar 内部实现，不新建组件文件）

- 结构复用 picker 弹层范式（styles.css L1229-1313）：`.rlib-mask`（fixed inset-0 z-25，≥560px 居中）+ `.rlib`（min(640px,100%) max-height 86vh flex column surface r-lg shadow）+ head（h3 配方库 + count 徽标 + 完成 btn）+ body（滚动列表）。
- 列表项 = 配方卡片：
  - 名称 + 徽标行：当前使用（primary 软底）· ⚠ flagBad 红标 · N 份 · X 种食材 · ≈Y kcal/份（recipeTotals 已在 recipeLib 数据里）
  - 内容预览一行：前 4 个食材名 + 「等 N 样」（foodById 映射，防溢出）
  - 操作钮（每卡右侧，icon btn）：载入 / 重命名 / 删除
- 交互细节：
  - 载入：已绑定条目直接关弹层无动作；未绑定时二次确认文案「载入将替换当前工作区（未保存的修改会丢失）」，确认后才走 loadRecipe(id)
  - 重命名：行内 input 切换（点铅笔 → input + 保存/取消），保存走新 `renameRecipe(id, name)` = `api.updateRecipe` 全量回写（用该条目自身数据 + 新 name，不掺工作区状态）+ refreshRecipes；重命名当前绑定条目时同步 store.recipe.name 与 recipeName
  - 删除：confirm 弹层（复用 .rlib 内嵌确认条，避免原生 confirm）「删除配方「N」？该操作不可撤销」，确认后走 deleteRecipeFromLib
  - 弹层内底部：「另存当前为新配方」btn（绑定态显示）——保留 saveAsNew 入口
- 关闭：mask 点击 / 完成 btn / Esc（监听 keydown，与 picker 一致不强制）

### 2.3 RecipeView 改动点（最小侵入）

- RecipeLibBar props 增 `recipesFull`（recipeLib 已含 totals/items，够用，无需新增——recipeLib computed 已 map flagBad，items/totals 在 store.recipes 原始数据里，弹层内自己 foodById）
- emits 增：无（载入/删除复用现有 @load/@delete；重命名与另存新增 @rename/@save-as 由弹层内 emit 给 RecipeView）
- RecipeView 新增 renameRecipe(id, name) 函数（~15 行）+ saveAsNew 复用
- 其余（saveRecipeToLib/openCook/分包/预演）零改动

### 2.4 不做的事（边界）

- 不动后端（PUT /recipes/:id 已支持 name 全量更新；DELETE 已有 404 防护）
- 不做拖拽排序/分组/搜索（当前库容量小，收益低）
- 不做覆盖 diff 对比视图（保留按钮文案级提示，diff 视图留待后续需求）
