## 1. 数据模型（新表三张，既有表只加列不动语义）

### exercises（动作库，SQLite 化）
```
id INTEGER PK, key TEXT UNIQUE NOT NULL,   -- 稳定键：既有19个原样迁移(key铁律)；新动作 slug 从英文名派生
name_zh TEXT NOT NULL, name_en TEXT,
equipment TEXT NOT NULL,                    -- dumbbell|bench|bodyweight|other（'other'=超出器械边界,默认停用）
category TEXT NOT NULL,                     -- push|pull|legs|core|shoulders|arms|cardio
gif_url TEXT, tips_json TEXT,               -- 中文要点3条（fetch 脚本二次创作）
source TEXT NOT NULL DEFAULT 'exercise_db', -- exercise_db|builtin|custom
enabled INTEGER NOT NULL DEFAULT 1,         -- 用户可停用；删除=enabled 0 软删(被 workout_sets 引用,不物理删)
created_at TEXT
```
- 种子迁移：19 个 builtin 原样入库；ExerciseDB 全量抓取→按 equipment∈{dumbbell,bench(utility=bench+equipment barbell? 否——只收 dumbbell/bodyweight/band-free),bodyweight} 过滤+中文名映射表→入库 `source='exercise_db'`。抓取脚本扩展 fetch_actions.py（输出 JSON→种子导入命令，**构建期一次性**，不进运行时依赖）。
- **备份三处齐备 + auditBackupCoverage**；CRUD API `/api/exercises`（GET ?enabled&category；POST custom；PUT 改名/启停；**无 DELETE**，软删）。

### workout_plans + plan_days（计划管理）
```
workout_plans: id INTEGER PK, key TEXT UNIQUE NOT NULL,  -- 'A'|'B'|'C' 保留内置；用户计划 'P<n>' 时序分配
  name TEXT NOT NULL, kind TEXT NOT NULL DEFAULT 'user', -- builtin|user
  goal TEXT, days_per_week INTEGER, archived INTEGER DEFAULT 0, created_at TEXT
plan_days: id INTEGER PK, plan_id INTEGER NOT NULL REFERENCES workout_plans(id) ON DELETE CASCADE,
  seq INTEGER NOT NULL,            -- 1..daysPerWeek 训练日序号（周历模板槽）
  label TEXT                       -- '推' '拉' '腿' '全身A' 等
plan_items: id INTEGER PK, day_id INTEGER NOT NULL REFERENCES plan_days(id) ON DELETE CASCADE,
  exercise_key TEXT NOT NULL, sets INTEGER NOT NULL DEFAULT 3, reps_target TEXT, ord INTEGER NOT NULL
```
- 内置 A/B/C 迁移为 kind='builtin' 三行（plan_days/items 由 PLANS 常量种子化）；**training.js PLANS 常量保留**作为种子源与 fallback，运行时改读 DB（key 铁律不动）。
- workout_logs.plan_key：校验从「∈A/B/C」放宽为「∈ workout_plans.key 全集」（后端查表校验）；既有数据不变。nextKey 轮换仅在「当前使用内置轮换计划」时生效（见 §3 周历，轮换逻辑被排课表替代时 nextKey 不再驱动今日页）。

## 2. 动作库页（设置入口+训练页双入口）

- 列表：分类分组（category），行=GIF缩略+中文名+器械标+启停开关；详情=GIF大图+tips+可编辑名。停用动作不出现在选择器，历史记录照常渲染。
- 选择器：加动作到计划日=抽屉（分类层→动作→选定），问卷「越全越好」由此满足（预计入库 200-400 个哑铃/自重动作）。

## 3. 周历排课（训练页新视图）

- 7 日网格（周一主首，复用 cardio weekStartKey 口径）：每格显示「排定：label / 完成：✓(workout_logs 有该日该计划记录) / 休息 / 空」。
- 数据表 `plan_schedule(id, date UNIQUE, plan_key, day_id NULL, rest INTEGER)`：date 主键唯一；rest=1 显式休息；NULL 行=未排（自动顺延兜底，见下）。
- **顺延规则**：当日有排定但未完成且已过 23:59 → 次日打开时该槽自动后移一位（纯读时派生实现：schedule 读时检查「今天之前未完成排定」→ 展示层顺延，**不改库**；与 pickDayType 读时派生同哲学，可回撤）。
- 排课操作：点格→选计划日/休息/清空；拖改=长按拖动到另一格（HTML5 drag 或 touch 简化=选中+点目标格两步实现，手机优先两步法）。
- 「今日练什么」卡（训练页首）：读 plan_schedule 今日槽；无排定→回退 nextKey 轮换+「按轮换」标注。

## 4. 一键生成一周计划（纯函数）

- `generateWeekPlan({ goal, daysPerWeek, equip边界 })` in training.js：goal∈gain/cut/maintain，days∈2-6。
- 分化模板：2-3天=全身×N；4天=上/下×2；5天=推/拉/腿/上/下；6天=推/拉/腿/推/拉/腿。
- 选动作：目标→category 权重（gain 力量复合优先/cut 保肌+core+cardio 权重）→按 sets/reps_target 模板填槽（gain 3-4×8-12 主项+2 辅；cut 3×12-15 循环+core）；从 exercises enabled 且 equipment∈边界选，不足回退 builtin。
- 输出 {name, days:[{label, items:[{exerciseKey,sets,repsTarget}]}]} → 用户确认页预览→可改→保存为 user plan。生成器纯函数可断言；模板可调权重后续迭代（v1 固定）。

## 5. 跟练模式（A方案）

- 从「今日练什么」进入：全屏跟练视图=当前动作大 GIF（80% 宽，循环播放）+动作名/目标组次+每组计时（准备 10s→做组不限时→完成点击→组间倒计时）。
- 组间倒计时：环形进度（复用 SPEC 7.6 环形设计），时长读 `settings.restSeconds`（新键，默认 90，范围 30-300，设置页训练区可调）；剩 10s 变色+震动（vibrate(200)）；跳过按钮。
- 完成=既有点击录组流（SPEC 7.6 预填/stepper/力竭）不重做——跟练视图底部保留「直接记组」切换，两条路进同一录组态。
- 语音提示不做（问卷未选）；订阅课程不做（裁决「不订阅」）。

## 6. 记一组 1 次点击（问卷裁决）

- 组行默认值=上次该动作组（weight+reps 预填既有）+「确认」按钮单点即录；RIR 默认空（阶段 1 不录，SPEC 7.2）；力竭一键标记保留。
- 预填源扩展：上次参考=同 exerciseKey 最近一组（既有）+ 同计划日上次（优先）。

## 7. 冻结边界

- workout_logs/workout_sets 列零改动；exercise_key 既有 19 个值不变；pickDayType 读时派生链不动（plan_schedule 不参与 dayType）；phaseOf/回归阶梯/e1RM/zone2Range 不动；备份 schema_version 顺延 3→4（eatery_dishes 未升过版本的核对：实施时以当前 schema_version 为准 +1）。
- SPEC 7.4 校验放宽（plan_key/exerciseKey 查库）= 后端两处校验点修改，属计划内变更（本详设覆盖），无需另出卡。
