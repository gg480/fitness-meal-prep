# 06 独立体重页-含围度子Tab · 详设 v1

> 依据：问卷裁决（体重默认有+体脂率+腰围 / 悬浮大按钮 / 一天一次后值覆盖 / 曲线近30天+全部+7日均线+目标虚线 / 进度低调 / 提醒搬体重页为主今日页轻提示 / 围度=体重页子Tab / 围度六部位腰臀大臂左右大腿左右 / 频率随缘 / 用途=看趋势+估算体脂率）+ 大纲 Tab 演进表（06 完成后 6 Tab：今日/目标/配方/体重/设置，记录 Tab 仍在——记录取消是 10 的事）。

## 0. 现状盘点（实施输入）

- 体重录入两处重复：LogView.vue L58-60（`api.addWeight(kg, dateKey())`，30-200 校验）、TodayView.vue L684-698（本日体重卡，同链路，`store.weights.find(w => w.d === key)` 判今日已录）；打卡前置（TodayView L1026-1035 未录体重不给打卡）。
- 曲线：LogView `renderChart(store.weights)`（L15/L49）SVG 细线每日+粗线 7 日均线，n<8 提示；均线「仅展示不参与判定」。
- 腰围：SettingsView L233-235 `settings.waist`（选填 40-200，null=不参与判定）→ RuleCard「向心性肥胖」提醒（男>85/女>80）。
- 目标体重：SettingsView L409（30-200，键名实施时核对 settings 白名单）。
- weights 表：`(date 主键, kg)`，upsert 后值覆盖——天然满足「一天一次后值覆盖」。
- RuleCard：evalRules(weights, portions, {lastRecalcWeight, waist})——引擎签名冻结，数据来源在 store 层可换。

## 1. 数据模型（最小增量）

- **weights 表加列 `body_fat REAL` 可空**（0-60，%）：体脂率与体重同录同行（晨起同一次测量），`migrateXxxColumns()` 幂等补列，老数据 NULL。API `addWeight(kg, date, bodyFat?)` 尾参扩展（T-128 尾参先例），不传=不清空旧值。
- **新表 `measurements(id, date, part, value, created_at)`**：part ∈ `waist/hip/upper_arm_l/upper_arm_r/thigh_l/thigh_r`（六部位枚举，后端校验 400）；value REAL 20-200 cm（腰围沿用 40-200 下限，其余放宽）。一天可多条（随缘记录，upsert 按当日最新覆盖或并列存——**并列存**，曲线取当日最新）。`CREATE TABLE IF NOT EXISTS` 幂等；**备份白名单三处齐备 + auditBackupCoverage() 不报红**（SPEC §8 eatery_dishes 先例）。
- **兼容**：规则引擎 `settings.waist` 不动——measurements 落 waist 时**同步回写 settings.waist**（store 层一次写入，引擎零改动，迁移期两边一致）；停止减脂提醒继续吃 settings.waist。
- API：`GET/POST /api/measurements`（?part 可选过滤；POST {date,part,value} 校验枚举+范围；拒未来日期同 training 先例）。

## 2. 页面结构（新 Tab「体重」）

```
┌─ 顶部：进度条（低调）─────────────┐
│ 当前 kg → 目标 kg（差值+百分比）   │ 仅文字+细进度条，无庆祝动画
├─ 主区：体重曲线卡 ────────────────┤
│ [近30天|全部] 切换                 │
│ 细线每日 + 粗线7日均线 + 目标虚线  │ renderChart 扩展虚线层
│ 体脂率小图（有数据才显示）          │
├─ 记录卡：体重 kg + 体脂率 %（选填）│
├─ 子Tab：[体重] [围度] ────────────┤
│ 围度：六部位行（值+日期）+趋势小图 │
│ 腰围行尾注「参与向心性肥胖判定」    │
└──────────────────────────────────┘
[＋] 悬浮大按钮（FAB，右下 56px，记体重/体脂/围度统一入口，分步表单）
```

- **曲线**：`renderChart` 增量——目标虚线（settings.goalWeight，虚线+右端标注值）；[近30天|全部] 前端过滤（weights 已全量在 store，无新 API）。体脂率第二曲线（右轴%或独立小卡，实施时取视觉简者，可逆不问询）。
- **估算体脂率（展示性，不入库）**：无实测体脂时显示 Deurenberg 公式估算值——`1.20×BMI + 0.23×年龄 − 10.8×性别(男1女0) − 5.4`，标注「估算值，以实测为准」；有实测则只显实测。
- **提醒搬迁**：RuleCard 体重类提醒卡移入体重页（规则引擎/evalRules 零改动，仅 UI 归属）；今日页保留一行轻提示「体重规则有新建议 → 体重页」（有 rule action 时才显示）。
- **打卡联动不变**：TodayView 本日体重卡保留（一键例行入口，不强制跳页——问卷裁决「提醒搬体重页为主今日页轻提示」指规则提醒，非录入入口）。

## 3. 冻结边界

- evalRules/calcQuotaProfile 签名与逻辑零改动；weights 既有语义（upsert、30-200）不变；settings.waist 键继续供规则引擎；potDaysOf/quota 不涉。
- 新增仅：weights.body_fat 列 + measurements 表 + 两条 API + 一个新视图 + renderChart 扩展。

1. body_fat 幂等补列 + addWeight 尾参写入/不传不清空。
2. measurements CRUD：枚举校验 400、范围校验 400、未来日期 400、当日多条取最新。
3. waist 回写：POST waist → settings.waist 同步（导入端不吃 settings 白名单 400）。
4. 备份对账：BACKUP_COLUMNS/导出/导入三处含 measurements，auditBackupCoverage 绿；旧备份（无该表）导入跳过不报错。
5. 曲线数据：近30天过滤边界、7日均线窗口、目标虚线取值（复用 calc-audit 既有断言口径回归）。
6. 估算体脂率：Deurenberg 三例（男/女/边界 BMI）数值断言。
